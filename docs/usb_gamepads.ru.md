# USB HID геймпады

[English version](usb_gamepads.md)

USB-геймпады и джойстики попадают в ядра как геймпад Sega MD2 (`CMD_JOYSTICK`): направления,
A B C X Y Z, Start и Mode. HID-геймпады и [XInput-геймпады](xinput.ru.md) делят два USB-порта.
Геймпад занимает первый свободный порт при подключении и держит его, пока не будет отключён.

HID-геймпад отображается одним из двух способов:

1. **Ini-драйвер.** Если в `/drivers/` на SD-карте есть ini с VID/PID геймпада, используется
   он (формат: [Ini-драйвер](#ini-драйвер) ниже). Его создаёт маппер в OSD (см. ниже), или его
   можно написать вручную, или сделать в браузерном
   [hidmapper](https://andykarpov.github.io/karabas-go-firmware/hidmapper/) (исходники в
   [`tools/hidmapper`](../tools/hidmapper)), который теперь нужен редко.
2. **Карта по умолчанию.** Иначе прошивка строит карту по HID-дескриптору отчётов геймпада
   (`lib/common/hid_auto_map.c`). Большинство геймпадов так работает без ini.
   Карта по умолчанию строится и для геймпада с драйвером: она включается, когда драйвер
   забыт.

## Маппер в OSD

Если карта по умолчанию геймпаду не подходит, настройте его в OSD: откройте Setup (`S` в
браузере ядер или в меню ядра), затем **Map USB gamepad**; в графической настройке браузера
ядер это вкладка **Gamepad**. Экраном управляют клавиатурой (а в графической настройке ещё и
мышью).

Экран открывается на двух джойстичных портах: геймпад на каждом (VID:PID) и то, чем он
отображается: его ini-драйвер, `default map` или `XInput`. **Forget** переименовывает ini-драйвер
выбранного геймпада (все для его VID/PID) в `*.ini.bak` и перезагружает драйверы: геймпад сразу
продолжает работать с картой по умолчанию. **Map** обучает геймпад:

1. Нажмите кнопку на геймпаде. Отображается первый геймпад, у которого изменился отчёт.
2. Отпустите всё и ненадолго оставьте геймпад в покое: маппер запоминает отчёт покоя и
   дрожание стиков. Нажатие в это время запускает этап заново.
3. Нажимайте каждую кнопку MD2, когда её запросят, и отпускайте. `Enter` пропускает кнопку
   (она пропускается и через 10 с), `Backspace` возвращает на одну назад.
4. `Enter` сохраняет `/drivers/<vid>_<pid>.ini`. Остальные ini для того же VID/PID
   переименовываются в `*.ini.bak`. Драйверы перезагружаются, и геймпад сразу работает по новой
   карте. В графической настройке нарисованный на экране геймпад после этого показывает
   кнопки, нажатые по новой карте.

Для каждого нажатия маппер сначала берёт ниббл hat, затем один бит, затем ось, которая
сдвинулась сильнее всех, как диапазон оси от середины между покоем и нажатием
(`lib/common/hid_learn`). Результат — обычный ini-драйвер, его можно править вручную.

## Ini-драйвер

Драйвер — это `/drivers/<anything>.ini` на SD-карте; маппер в OSD называет его
`<vid>_<pid>.ini`. Строки комментариев начинаются с `;`, каждая строка должна умещаться в 79
символов.

```ini
[info]
; VID / PID геймпада, hex, в нижнем регистре
vid = 081f
pid = e401
; необязательно: имя для лога
name = Retrolink USB Gamepad
; необязательно: только отчёты с этим id (десятичное), для геймпадов, которые
; шлют ещё и отчёты батареи или вендора; без него отображается каждый отчёт геймпада
; report_id = 1

[buttons]
up = 1,0,0
down = 1,0,255
left = 0,0,0
right = 0,0,255
a = 5,1,5
b = 5,1,6
c = 6,1,0
x = 5,1,4
y = 5,1,7
z = 6,1,1
start = 6,1,5
mode = 6,1,4
```

Каждая из 12 кнопок MD2 (`up`, `down`, `left`, `right`, `a`, `b`, `c`, `x`, `y`, `z`, `start`,
`mode`) принимает один или несколько источников, разделённых `|` (без пробелов), каждый в виде
`pos,type,value[,arg]`. `pos` — номер байта в отчёте с 0, после байта report id, если у геймпада
есть report id.

| type | нажато, когда |
| --- | --- |
| 0 | байт `pos` равен `value` (0..255) |
| 1 | бит `value` (0..7) байта `pos` установлен |
| 2 | hat: младшие 4 бита байта `pos`, сдвинутые вправо на `arg` (0..4, по умолчанию 0), равны `value` (0..7, 0 = вверх, по часовой стрелке) или соседней с ним диагонали; 8..15 — центр |
| 3 | `value` <= байт `pos` <= `arg` (диапазон оси) |
| 4 | бит `value` байта `pos` сброшен |

Ещё примеры:

```ini
up = 1,3,0,63|5,2,0   ; stick вверх (байт 1 меньше 64) или hat вверх
right = 5,2,2,4       ; hat вправо, hat в старших 4 битах байта 5
start = 2,4,0         ; кнопка, которая читается как 0 при нажатии
```

Типы 0 и 1 — исходный формат, поэтому старые ini работают без изменений. В ini-драйвере может
быть до 32 источников. Чтобы найти байты вручную в Linux: `lsusb` для VID / PID, затем
`sudo usbhid-dump -e stream -d <vid>:<pid>` и нажимайте кнопки по одной; или воспользуйтесь
[браузерным маппером](https://andykarpov.github.io/karabas-go-firmware/hidmapper/).

## Карта по умолчанию

Используются только коллекции дескриптора joystick / gamepad / multi-axis.

| HID | MD2 |
| --- | --- |
| первая ось X / Y (левый стик или d-pad, отдаваемый осями) | направления, при отклонении от центра больше чем на четверть диапазона |
| hat switch | направления, с диагоналями |
| usage D-pad up / down / right / left | направления |
| Button 1 / 2 / 3 / 4 | X / A / B / Y |
| Button 5 / 6, Button 7 / 8 | C / Z |
| Button 9, usage Select | Mode |
| Button 10, usage Start | Start |

Порядок кнопок такой же, как у распространённых геймпадов в стиле SNES / PlayStation: 1 сверху,
2 справа, 3 снизу, 4 слева, затем бамперы, select и start. Геймпады, которые нумеруют кнопки
иначе, получают другую раскладку. Для них напишите ini-драйвер.

Отчёты с другими report id (батарея, данные вендора) кнопки не трогают. Геймпады, у которых есть
только vendor-defined коллекции, нельзя отобразить по умолчанию, им нужен ini-драйвер.

## Диагностика

Поставьте `debug=1` в `karabas.ini`. При подключении геймпада в логе появляется
`uses its driver <file>` и / или `HID default map: N fields`, а итоговое слово кнопок выводится
как `SEGA L` / `SEGA R`.

Сырые отчёты геймпада показывает
[браузерный маппер](https://andykarpov.github.io/karabas-go-firmware/hidmapper/) (WebHID). Его
дескриптор отчётов можно прочитать на Linux-ПК командой `usbhid-dump -d <vid>:<pid> -e descriptor`;
этого достаточно, чтобы добавить тест для нового геймпада в `test/test_hid_auto_map`.
