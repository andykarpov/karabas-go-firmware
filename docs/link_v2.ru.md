# Линк MCU ↔ FPGA v2 (черновик)

[English version](link_v2.md) · Линк v1: [protocol.ru.md](protocol.ru.md), [burst_protocol.ru.md](burst_protocol.ru.md)

Статус: **черновик, ничего не реализовано**. Линк v2 — второй протокол на тех же проводах. Он
живёт рядом с v1: файл ядра говорит, на каком линке ядро работает, и прошивка сохраняет v1 для
всех ядер, которые не заявили v2.

## 1. Зачем

Устройство v2 взято из SPI-протокола MiSTle FPGA Companion
([SPI.md](https://github.com/MiSTle-Dev/FPGA-Companion/blob/main/SPI.md), `mcu_spi.v` /
`sysctrl.v` / `osd_u8g2.v` из MiSTeryNano): один chip select на сообщение любой длины, маленькие
автоматы целей в FPGA, линия прерывания от FPGA с регистром статуса и монохромный растровый OSD,
который рисует MCU. С MiSTle по проводам **не совместим**: коды, цели и режим SPI наши (SD-карта
у плат Karabas на MCU, а не на FPGA).

Что исправляется по сравнению с v1:

| v1 | v2 |
|---|---|
| 3-байтный кадр на каждый байт данных, chip select вокруг каждого кадра | Один пакет на сообщение: отчёт клавиатуры — один пакет в 10 байт вместо 7 кадров, сектор — один пакет около 520 байт |
| FPGA может говорить только в ответных байтах, прошивка опрашивает её NOP-кадрами | FPGA поднимает INT; прошивка читает регистр статуса и обслуживает цели, которые просили |
| Очередь ответов 512 × 24 бита в каждом ядре (`kg_mcu_link`) | Маленькие регистры / FIFO целей, MCU читает их по INT |
| Bursts на втором chip select со своим заголовком | Любой пакет — burst; второго chip select нет |
| Текстовый OSD: сетка символов / атрибутов и шрифт в FPGA | Монохромный растр 256 × 128; шрифты и рисование в MCU (u8g2) |

## 2. Физический уровень

| Сигнал | Направление | В v2 |
|---|---|---|
| `MCU_SCK` | MCU → FPGA | Тактовый SPI: 16 МГц по умолчанию, до 32 МГц (раздел 9) |
| `MCU_MOSI` | MCU → FPGA | |
| `MCU_MISO` | FPGA → MCU | FPGA ведёт его только пока `MCU_SS` в нуле |
| `MCU_SS` | MCU → FPGA | Выбор пакета, активный 0. Единственный chip select линка |
| `INT` | FPGA → MCU | Прерывание, **активная 1**, по уровню |
| IO0 | (MCU → FPGA) | Резерв (burst chip select из v1). MCU держит его входом, ядра его не ведут |

INT — это линия `BURST_READY` из v1: она уже идёт от FPGA к MCU, а на входе MCU есть подтяжка к
нулю. Пока FPGA конфигурируется, и с ядром v1, читается 0 (прерывания нет).

| Плата | INT: GPIO RP2040 (прошивка) | Порт FPGA в топе ядра | Пин FPGA |
|---|---|---|---|
| Go | GPIO2 (`PIN_MCU_SPI_IO1`) | `MCU_SPI_IO[0]` | N9 |
| Mini | GPIO15 (`PIN_MCU_SPI_IO1`) | `MCU_IO[1]` | F6 |
| Mini G | GPIO15 (`PIN_MCU_SPI_IO1`) | `MCU_IO[1]` | F6 |

На Go индекс порта FPGA переставлен, как и для bursts в v1.

SPI mode 0 (CPOL 0, CPHA 0), старший бит первым, байты по 8 бит. (В MiSTle mode 1; v2 оставляет
режим `kg_spi_slave`.) Chip select FT812 и SD2 остаются как в v1 (`SPI_CONTROL`, раздел 5.1).

## 3. Пакеты

```
MCU_SS  ‾‾\________________________________________________/‾‾
MOSI       T    C    P0   P1  ...  Pn-1   00   00  ...  00
MISO       x    x    x    x   ...  x      x    D0  ...  Dm-1
```

- `T` — цель (раздел 4), `C` — команда этой цели, `P0..Pn-1` — её параметры. Спад `MCU_SS`
  начинает новый пакет; все цели при этом забывают недопринятый пакет. Подъём `MCU_SS` его
  заканчивает.
- У команды, которая возвращает данные, после последнего параметра идёт **один байт разворота**
  (MCU шлёт 0, выход FPGA не определён), затем данные `D0..Dm-1` (MCU шлёт 0). Разворот даёт цели
  время одного байта, чтобы положить `D0` в сдвиговый регистр. После `D0` цель отдаёт байты из
  регистра или буфера, который читает с упреждением, так что поток в 512 байт идёт без пауз.
- MCU может закончить пакет раньше: FPGA отбрасывает то, что не ушло. Чтение за концом данных
  даёт 0.
- Многобайтные числа — little-endian (как в v1).
- Неизвестные цели и команды игнорируются до подъёма `MCU_SS`.
- Цели никогда не нужны паузы между байтами. MCU может их делать (побайтовые передачи); FPGA не
  должна от них зависеть.
- Команды с «повторяемыми» параметрами (`SETVAL`, `PS2`, `PUT`) принимают сколько угодно записей
  в одном пакете.

Управление потоком — внутри протокола: цель, которая не может принять данные, сообщает это в
команде статуса (`LOAD STATUS`, `PORT STATUS`), и MCU спрашивает перед отправкой. Линии READY нет.

## 4. Цели и прерывания

| T | Цель | Бит IRQ | Заменяет в v1 |
|---|---|---|---|
| `00` | SYS: идентификация, прерывания, настройки, параметры платы | 0 | `CMD_CAPS`, `HW_SETUP`, `SWITCHES`, `INIT_*`, `SPI_CONTROL`, `BTN`, `FLASHBOOT`, `DEBUG_*` |
| `01` | HID: клавиатура, мышь, джойстики, PS/2 | 1 | `USB_KBD`, `USB_MOUSE`, `JOYSTICK`, `PS2_SCANCODE`, `MATRIX_BTN` |
| `02` | OSD: растровый оверлей | 2 (не используется) | `CMD_OSD` |
| `03` | IMG: смонтированные образы, сектора, backup RAM, дисководы | 3 | `40`..`4A`, `48`, `49` |
| `04` | LOAD: ROM, файловый загрузчик, ioctl-загрузчик | 4 | `ROM*`, `FILE*`, `IOCTL*`, bursts |
| `05` | PORT: байтовые потоки (UART, ESP, MIDI, принтер) | 5 | `UART`, `ESP_UART`, `MIDI`, `13`/`14` |
| `06` | RTC | 6 | `CMD_RTC` |
| `07` | AUX: LED-матрица, пики звука, отладочные значения | 7 | `60`..`63`, `70`/`71`, `30`/`31` |

### Линия прерывания

`INT = (pending != 0)`, `pending` — 8 бит, по одному на цель. Цель держит свой бит, пока у неё
есть что-то для MCU (событие в очереди, данные на чтение), и сама снимает его, когда MCU всё
прочитал. MCU подтверждает только «фронтовые» причины SYS (раздел 5.1).

Прошивка: прерывание GPIO по уровню (1) на INT будит задачу линка и выключается; задача читает
`SYS IRQ`, обслуживает каждую цель с поднятым битом и снова включает прерывание GPIO. Опроса
NOP-ами нет. Пока v2 новый, остаётся редкое контрольное чтение `SYS IRQ` (около 100 мс), его
находки пишутся в лог при `debug=1`.

## 5. Команды

`→` — параметры от MCU, `←` — данные от FPGA (после байта разворота).

### 5.1 SYS (`00`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `00` | `STATUS` | | `'K' 'G'`, версия (2), caps (2 байта), ширина OSD / 8, высота OSD / 8, маска портов | Первый пакет после конфигурации; сигнатура говорит, что ядро работает и говорит на v2 |
| `01` | `IRQ` | маска подтверждения | pending | `pending` до подтверждения. Подтверждение снимает только причины SYS (бит 0) |
| `02` | `IRQ_SRC` | | причины SYS | бит 0 coldboot, бит 1 запрос перезагрузки; чтение снимает бит 0 |
| `03` | `SETVAL` | (индекс, значение) × n | | Переключатели OSD, на старте все одним пакетом; индекс = индекс переключателя v1 (`sw` в kgo2), так что закреплённые `index` продолжают работать. Триггеры: 1, через 100 мс 0 |
| `04` | `HW_SETUP` | ключ, байты значения | | байт значения k — это ключ + k: 0 плата (`HW_ID`), 1 только DVI, `10`..`17` сборка ядра, `18`..`1F` сборка прошивки: плата + DVI одним пакетом, 16 символов сборок другим |
| `05` | `INIT` | 1 = начало (busy) / 0 = готово | | Как `CMD_INIT_START` / `CMD_INIT_DONE` |
| `06` | `SPI_CONTROL` | биты | | Как `CMD_SPI_CONTROL`: бит 0 SPI FT812, 1 видео FT812, 2 SD2, 3 ESP8266, 4 сброс FT812 |
| `07` | `BTN` | кнопка, состояние | | 0, 1 кнопки платы с действием `core`; 2..5 кнопки дополнения LED-матрицы (v1 `CMD_MATRIX_BTN`) |
| `08` | `RELOAD` | | id ядра | Читается после бита 1 `IRQ_SRC` (v1 `CMD_FLASHBOOT`) |

Caps (байты 3..4 `STATUS`): бит 0 IMG, 1 backup RAM, 2 образы с защитой от записи, 3 дисководы
(DSKCHG), 4 управление потоком LOAD (`LD_READY`), 5 RTC, 6 AUX, 7 видео FT812, 8 перезагрузка,
9 MIDI IN. Маска портов говорит, какие индексы PORT есть у ядра (бит n = порт n).

Coldboot: причина SYS бит 0 ставится, когда линк ядра выходит из сброса. Прошивка видит её после
своей конфигурации (и снимает), а также когда ядро сбрасывает свой линк во время работы
(перезагрузило себя или упало): тогда прошивка заново выполняет стартовую последовательность
(раздел 6) без загрузки битстрима.

### 5.2 HID (`01`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `KBD` | 8 байт: модификаторы, 0, 6 кодов клавиш | | USB boot report; для ядра один строб на отчёт (`KBD_WR`). Не шлётся при открытом OSD |
| `02` | `PS2` | (вид, код) × n | | вид 0 байт set 2, 1 байт XT (бит 7 кода = отпускание): строб на байт (`PS2_WR`), все байты клавиши (префиксы E0 / F0, автоповтор) одним пакетом |
| `03` | `MOUSE` | dx, dy, колесо, кнопки | | Знаковые приращения; один строб на отчёт (`MS_WR`) |
| `04` | `JOY` | (порт, биты 7..0, биты 15..8) × n | | Биты v1; оба порта одним пакетом, если изменились оба (`JOY_WR`) |
| `06` | `EVENT` | | число n, затем (команда, аргумент) × n | PS/2-команды ядра клавиатуре (`ED` светодиоды, `F0` набор); бит IRQ 1 |

### 5.3 OSD (`02`)

OSD — монохромный растр **256 × 128 точек** (4096 байт) в страничной раскладке u8g2 и маленьких
OLED: 16 страниц по 8 строк; в странице байт x — точки столбца x, бит 0 сверху. Размер берётся из
`STATUS` (байты 5..6), так что ядро с недостатком блочной памяти может предложить 128 × 64.

| C | Имя | → | Примечание |
|---|---|---|---|
| `01` | `ENABLE` | бит 0 показать | |
| `02` | `WRITE` | тайл (2 байта, LE), байты данных | тайл = страница × (ширина / 8) + столбец / 8; байты идут от `тайл × 8`, по кругу в конце. u8g2 шлёт по ряду тайлов |
| `03` | `COLORS` | fg R G B, bg R G B, непрозрачность bg: 0 нет фона, 1 половина, 2 три четверти, 3 сплошной | По умолчанию белое на тёмно-синем, 2 (прошивка ставит 3) |
| `04` | `POPUP` | x, y, w, h (в тайлах), место, zoom | Показывать только эту часть растра, как всплывающее окно; w = 0 — конец popup (снова весь растр). Место: 0 центр, 1 верх, 2 низ экрана. zoom: 0 масштаб OSD, 1 вдвое больше (как крупные клетки popup в v1) |

Ядро масштабирует растр целым множителем под свой видеорежим (×2 при ширине 640 / 800, ×3 или ×4
для 1024 × 768 и выше), ставит его в центр и рисует рамку и тень, как `osd_u8g2.v`. Окно popup
получает такие же рамку и тень. `ENABLE` и `POPUP` независимы, как в v1 (show и popup): OSD
виден, пока включено хоть одно; при обоих включённых показывается окно.

Монохромный намеренно: одна пара цветов на весь OSD (в v1 было 16 цветов ink / paper на клетку).
Выделение рисуется (инверсные полосы, рамки, значки, шрифты). Цветовых плоскостей не будет.

#### Popup и диалоги

Что v1 делает с OSD и как это ложится на v2:

| v1 | Где | v2 |
|---|---|---|
| Режим popup: клетки вдвое крупнее при скрытом меню; всплывашка хоткея (логотип, имя пункта и значение, 500 мс) | `hotkey_popup()`, `ui_popup_start()`, `osd_show_popup()` | MCU рисует всплывашку в области растра и показывает её `POPUP` (zoom 1, место верх или центр); через 500 мс прячет `POPUP w = 0` и `ENABLE 0`. Клавиши продолжают идти в ядро |
| Прогресс поверх скрытого меню: «Loading...» загрузчиков, «Saving...» backup RAM, «Run SAV» | `osd_progress_popup()`, `osd_loading_popup()` | Диалог прогресса (ниже), показанный через `POPUP` (zoom 0, центр) |
| Прогресс поверх открытого меню | те же функции, рисуют в клетки меню | Тот же диалог поверх меню в кадровом буфере MCU; без `POPUP` |
| Номер popup для собственного оверлея ядра (`ADDR_POPUP` биты 7..4) | ядра со своей графикой popup | Убирается: все всплывающие окна рисует MCU |

Прошивка держит экран меню в своём кадровом буфере, а popup и диалоги рисует во втором слое;
после диалога она заново шлёт закрытые им тайлы. Обновление прогресса шлёт только ряд тайлов
полосы (одна страница в 8 строк, не больше 256 байт: меньше 0,1 мс на 32 МГц), так что полоса
может двигаться на каждом 512-байтном секторе, не замедляя передачу.

Виды диалогов слоя UI (раздел 8), одинаковые для v1 (текстовые клетки) и v2 (растр):

- **toast**: одна-две строки, таймаут, клавиш не берёт (значения переключателей по хоткею,
  «Disk A: game.adf»);
- **progress**: заголовок, строка текста, полоса с процентами, по желанию байты / оставшееся
  время; клавиш не берёт, кроме Esc там, где операцию можно прервать (загрузка файла);
- **busy**: заголовок и бегущий индикатор, когда длительность неизвестна (ожидание ядра, Wi-Fi);
- **message / confirm**: текст и OK или Да / Нет (сброс настроек, перезапись, ошибки), модальный:
  клавиши идут в диалог.

### 5.4 IMG (`03`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `MOUNT` | слот, размер (8 байт), флаги | | размер 0 = извлечь. Флаги: бит 0 защита от записи, бит 1 / 2 физический дисковод DS0 / DS1 (Go) |
| `02` | `EVENT` | | вид, слот, аргументы (5) | Сначала Z; одно событие на чтение (чтение `вида` его забирает), бит IRQ 3, пока есть ещё. Виды ниже |
| `03` | `RDATA` | слот, 512 байт, сумма (2) | статус | Z перед статусом. Сектор запроса чтения; статус 0 принят, 1 отказ (неверная сумма, нет ждущего чтения): MCU шлёт снова |
| `04` | `WDATA` | слот | 512 байт, сумма (2) | Z после слота. Сектор запроса записи, из буфера ядра |
| `05` | `DONE` | слот, статус | | 1 готово, 2 ошибка, 3 защита от записи (данные отброшены) |
| `06` | `FLUSH` | слот | | Backup RAM: записать грязные сектора сейчас; ответ придёт событием |
| `07` | `FDD_CHNG` | дисковод, значение | | Ответ на событие DSKCHG: 1 сменён / нет диска, 0 диск есть, 2 нет линии |

События (вид в `EVENT`):

| вид | Значение | Аргументы |
|---|---|---|
| 0 | нет | |
| 1 | запрос чтения | LBA (4) |
| 2 | запрос записи (сектор ждёт в ядре: `WDATA`) | LBA (4) |
| 3 | flush закончен | 1 грязных секторов не осталось / 2 запись не удалась |
| 4 | монтирование backup RAM | размер в секторах (4), вид файла (0 `.sav`) |
| 5 | запрос DSKCHG (ядро держит дисковод выбранным до `FDD_CHNG`) | дисковод (1 DS0, 2 DS1) |

Один запрос на слот за раз, как в v1; ядро повторяет запрос через 200 мс без `DONE`.
Секторный интерфейс `img_sdc` (`sdc_*`) остаётся для дисководов ядер; его сторона линка новая
(`kg_l2_img`), `kg_bk_ram` и `hdf_ata` сидят на нём, как сейчас (раздел 11).

### 5.5 LOAD (`04`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `START` | вид, слот, размер (8), расширение (ASCII, до 8) | | вид 0 ROM (ядро держит CPU в сбросе), 1 файловый загрузчик, 2 пункт `FL`; `LD_START` на такт после размера (новый файл: ядро сбрасывает то, во что грузит), `LD_ACTIVE` до `END` |
| `02` | `DATA` | вид, адрес (4), 1..512 байт | | Байт k по адресу + k (`LD_WR` на байт); пакет другого вида, чем открытый `START`, отбрасывается |
| `03` | `END` | вид | | `LD_ACTIVE` снимается, `LD_END` на такт |
| `04` | `STATUS` | | 1 = можно пакет `DATA` в 512 байт (`LD_READY`), 0 = ждать | Только с битом caps 4; без него ядро принимает `DATA` с любой скоростью (байт за 250 нс на 32 МГц) |

С битом caps 4 MCU читает `STATUS` перед каждым пакетом `DATA` и, пока там 0, опрашивает раз в
1 мс, не дольше 100 мс.

### 5.6 PORT (`05`)

Байтовые потоки, индекс порта = `P0` каждой команды.

| Порт | Поток |
|---|---|
| 0 | USB-последовательный порт / адаптер USB-UART (v1 `CMD_UART`: ZiFi, EVO RS232) |
| 1 | Модуль ESP8266 за FPGA (v1 `CMD_ESP_UART`) |
| 2 | MIDI IN от USB MIDI-клавиатуры (только MCU → FPGA, v1 `CMD_MIDI`; без счётчика байтов: MCU шлёт только то, что влезает, потерянные байты считает сам) |
| 3 | USB-принтер (только FPGA → MCU) |

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `STATUS` | порт | свободно rx, доступно tx, конфигурация (4) | конфигурация: порт 0 делитель DLL, DLM (0 = 115200), порт 3 флаг запроса статуса |
| `02` | `PUT` | порт, байты | | MCU → ядро; не больше свободного rx |
| `03` | `GET` | порт, число | столько байт | ядро → MCU |
| `04` | `PSTAT` | порт, статус | | Статус в ядро: порт 3 принтер (бит 7 BUSY) |

Бит IRQ 5, пока у какого-нибудь порта есть байты tx.

### 5.7 RTC (`06`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `SET` | первый регистр, значения | | Все регистры на старте, регистры времени каждые 500 мс (форматы `rtc_mode` из v1) |
| `02` | `GET` | | число n, (регистр, значение) × n | Регистры, которые записал CPU ядра; бит IRQ 6 |

### 5.8 AUX (`07`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `MATRIX` | | управление, 32 байта битовых плоскостей | Картинка ядра для LED-матрицы (байты 0..7 красные строки левой матрицы, 8..15 её зелёные, 16..31 правая; управление: бит 2 яркость в битах 7..4, бит 3 режим индикатора). Ядро рисует в свои плоскости (точками или строками), MCU читает их целиком, когда они изменились |
| `02` | `PEAKS` | | левый (2), правый (2) | Пики звука для индикаторов матрицы, не чаще ~50 раз в секунду |
| `03` | `DEBUG` | | addr (2), data (2) | Отладочные значения ядра для лога, когда изменились |

Бит IRQ 7, пока что-то из них изменилось с последнего чтения.

## 6. Старт ядра

1. Битстрим через выводы конфигурации.
2. `SYS STATUS`, пока не ответит `'K' 'G' 2` (не дольше 100 мс; INT может уже стоять из-за
   coldboot). Нет ответа: ядро считается незапущенным.
3. `SYS IRQ_SRC` (снимает coldboot), `SYS INIT 1`.
4. `SYS HW_SETUP`: плата, только DVI, оба id сборки.
5. ROM: `LOAD START 0`, `DATA`…, `END 0`.
6. `SYS SETVAL` со всеми переключателями одним пакетом, `RTC SET` со всеми регистрами.
7. `HID KBD` с пустым отчётом, `IMG MOUNT` сохранённых образов, автозагрузка `FL`.
8. `SYS INIT 0`. Включается прерывание GPIO на INT.

Загрузки шрифта нет (шрифт в MCU), запроса caps кроме `STATUS` тоже.

## 7. Выбор линка: core.json и kgo2

- `core.json`: `"link": 2` на верхнем уровне или для платы (`boards.minig.link`), по умолчанию 1.
- kgo2: в записи CORE появляется поле `link` (смещение 16, 1 байт; запись растёт, старые читатели
  его пропускают). Битстрим v2 кладётся в новый тип секции **10 `BITSTREAM_LINK2`**, а не в 9.
  Старая прошивка тогда не находит битстрима для своей платы и считает файл не ядром для этой
  платы, вместо того чтобы загрузить его и говорить с ним на v1. make_core пишет тип 10 для платы
  с link 2 и отказывает в `link` 2 для выхода `.kg1/.kg2/.kg3`.
- Строки меню — UTF-8 (имена по-русски); ядро v1 остаётся на ASCII / CP866, как сейчас.

## 8. Рисование OSD в прошивке

- u8g2 (BSD 2-clause) в `third_party/u8g2`, полнобуферный дисплей 256 × 128 (или размера из
  `STATUS`) в RAM MCU (4 КБ). Прошивка шлёт только изменившиеся ряды тайлов.
- Слой отображения под кодом меню: текстовый бэкенд v1 (`lib/osd`, `osd_ui`) и бэкенд u8g2 v2
  делят меню, файловый браузер и диалоги (toast, progress, busy, message / confirm, раздел 5.3):
  вызывающие (`hotkey_popup()`, загрузчики, `bk_save`, `uknc_sav`) просят диалог, а не клетки.
  OLED из бэклога может взять бэкенд u8g2.
- Экраны (`ui/ui2`, `ui/osd2`; согласованы на плате 2026-11-12):
  - Шрифт только `u8g2_font_6x12_t_cyrillic` (жирные пробовали и отказались: буквы сливаются),
    `u8g2_font_5x8_t_cyrillic` для хоткеев, пояснений, часов, неактивных строк.
  - Шапка (y 0..11, линия на 12): на главной странице имя ядра от левого края; на всех уровнях
    ниже треугольник «назад» и заголовок (путь страницы «Options > Video», приложение,
    «Disk 8: /dir» у браузера). Справа часы, в браузере вместо них его расширения.
  - 9 строк по 12 пикселей, без строк подсказок; справа полоса прокрутки.
  - Приложения настройки (Setup RTC, Map USB gamepad; у загрузочного ядра ещё Wi-Fi, Settings) и
    About — последние пункты главной страницы после разделителя.
  - Переключатели: Left / Right и хоткей листают значения; Enter открывает экран значений
    (радиокнопки, Up / Down, Enter выбирает, Esc назад). Пары Off / On, No / Yes, Disabled /
    Enabled — чекбокс; радиогруппы — кружки.
  - Фокус: залитая полоса / кнопка — в фокусе, рамка — выбранное, пока фокус в другом месте
    (порт в Map USB gamepad).
  - Окна по центру с пустым полем вокруг, toast по центру (увеличенный popup), About с логотипом
    OLED (на Go без «mini»). Фон непрозрачный (COLORS alpha 3).
  - Потом (бэклог): бегущая строка длинных имён, значки активности.
## 9. Сторона FPGA (karabas-go-modules)

- `kg_l2_link`: транспорт: сдвиговый регистр на `MCU_SCK` (`kg_spi_slave`, 8 бит, mode 0,
  фильтр chip select из `kg_mcu_link`), позиция в пакете, байтовая шина целей (`stb`, `tgt`,
  `cmd`, `n`, `d`) и их ответы (`rq`, `rq_m` -> `q`, один байт разворота), `INT` = ИЛИ их битов.
- Цели `kg_l2_sys`, `_hid`, `_load` (Ф2), `_osd`, `_img`, `_port`, `_rtc`, `_aux` (позже), каждая
  за параметром `ENABLE_*`.
- `kg_mcu2`: модуль ядра v2. **В нём нет ничего от линка v1** (ни кадров, ни burst, ни очереди
  ответов) и **свои порты со стороны ядра** (раздел 11): ядро переходит на v2 правкой своего
  топа (новые порты), пином INT (линия IO1, у burst-ядер это уже burst ready) и `"link": 2`.
- Такт: должно работать 32 МГц SCK при такте ядра около 28 МГц (bursts v1 так работают); точная
  граница будет из симуляции `kg_l2_spi` и запишется сюда.
- Ожидаемая экономия на ядро: уходят очередь ответов (512 × 24) и `kg_burst_rx`, уходит RAM
  шрифта OSD; растру OSD нужно 4 КБ (2 RAMB16). Измеряется на первых ядрах.

## 10. План

Одна ветка и один PR на фазу и репозиторий.

| Фаза | Работа |
|---|---|
| Ф0 | Эта спецификация |

Пилотное ядро на Mini G: **vic20** (сделано: Mini G на плате работает); boot-ядро переходит в Ф3 / Ф5 (ему нужны OSD, порты ESP и MIDI). Перевод ядра: karabas-go-modules `docs/link_v2_migration.md` |

## 11. Схемы v1 в v2

Ядро v2 не сохраняет способ v1 ни для одной функции: каждая переделана в пакеты, которые несут
сообщение целиком (отчёт, набор регистров, сектор) за один chip select, и в порты `kg_mcu2` со
стороны ядра, которые отдают ядру сообщение целиком одним стробом. Ядра под это правятся.

| Схема | v1 | Пакеты v2 | `kg_mcu2` со стороны ядра | Правка ядра |
|---|---|---|---|---|
| Старт ядра | `CMD_CAPS` с опросом NOP-ами, `INIT_START`, `HW_SETUP` по кадру на байт (18 кадров на id), загрузка шрифта | `SYS STATUS` (сигнатура, caps, размер OSD), `INIT 1`, `HW_SETUP` плата + DVI одним пакетом и 16 символов сборок другим, `INIT 0`; без шрифта | `HW_ID`, `DVI_ONLY`, `CORE_BUILD`, `FW_BUILD`, `BUSY` | нет (те же сигналы) |
| Опрос прошивкой | NOP-кадр на каждом проходе главного цикла, ответы в байтах любого кадра | `INT` (IO1, активная 1), `SYS IRQ` / события целей читаются, только когда INT = 1 | `MCU_INT` | пин IO1: у burst-ядер это burst ready, теперь выход `kg_mcu2` |
| Переключатели OSD | `CMD_SWITCHES` по кадру на переключатель, `kg_soft_switches` держит 16-битную команду | `SYS SETVAL` (индекс, значение) × n: на старте все одним пакетом, при изменении одна пара | `SW_WR`, `SW_INDEX`, `SW_VALUE` | регистры переключателей ядра берут `SW_WR` (вместо `kg_soft_switches` помощник, держащий их вектором) |
| Кнопки | `CMD_BTN`, `CMD_MATRIX_BTN` | `SYS BTN` 0..1 плата, 2..5 матрица | `BTNS` | нет / кнопки матрицы, если нужны |
| Перезагрузка ядра | `CMD_FLASHBOOT` в очереди ответов | `SYS IRQ_SRC` бит 1, `SYS RELOAD` | `RELOAD_REQ`, `RELOAD_CORE` | нет |
| FT812, SD2 | `CMD_SPI_CONTROL`, chip select транзитом | `SYS SPI_CONTROL` | `FT_*`, `SD2_*`, как в `kg_mcu` | нет |
| Клавиатура | 7 кадров на отчёт, `KB_DAT0..5` / `KB_STATUS` меняются побайтно | `HID KBD` 8 байт | `KBD` (56 бит) с `KBD_WR` | клавиатура ядра берёт отчёт по `KBD_WR` (без полуобновлённого отчёта) |
| PS/2, XT | кадр на байт, переключатели `KB_SCANCODE_UPD` / `XT_SCANCODE_UPD` | `HID PS2` (вид, код) × n: все байты клавиши одним пакетом | `PS2_CODE`, `PS2_KIND`, строб `PS2_WR` | детекторы переключения -> строб |
| Команды клавиатуре от ядра | `CMD_PS2_SCANCODE` в очереди ответов | `HID EVENT` (число, (cmd, arg) × n), бит IRQ 1 | `PS2_CMD`, `PS2_CMD_WR` | нет |
| Мышь | 4 кадра, `MS_UPD` переключается на байте кнопок, `MS_Z` 4 бита | `HID MOUSE` 4 байта | `MS_X`, `MS_Y`, `MS_Z` (8 бит), `MS_B`, `MS_WR` | переключатель -> строб; колесо 8 бит |
| Джойстики | 2 кадра на порт, 13 бит | `HID JOY` (порт, lo, hi) × n | `JOY_L`, `JOY_R` (16 бит), `JOY_WR` | ширина (биты 13..15 свободны под кнопки) |
| ROM | `ROMLOADER`, `ROMBANK` + `ROMDATA` на байт или bursts (второй chip select, `BURST_READY`) | `LOAD START 0`, `DATA` (вид, адрес, до 512 байт), `END 0` | шина `LD_*`, `LD_KIND` 0 | `ROMLOAD_*` -> `LD_*` |
| Файловый загрузчик (ядра `fileloader`) | уровни `FILELOADER` 3 / 2 / 0, `FILEBANK` + `FILEDATA` или bursts | `LOAD START 1` / `DATA` / `END 1` | `LD_*`, `LD_KIND` 1, `LD_START` = сброс нового файла | `FILELOAD_*` -> `LD_*` |
| Пункты FL (ioctl) | `IOCTL_STATE`, `SLOT`, `SIZE` × 8 дважды, `EXT`, `BANK` + `DATA` или bursts | `LOAD START 2` (слот, размер, расширение одним пакетом) / `DATA` / `END 2` | `LD_*`, `LD_KIND` 2, `LD_SLOT`, `LD_SIZE` | как выше; выбор `FILE_TO_ROM` / `FILE_WR_EACH` уходит в ядро |
| Управление потоком загрузки | линия `BURST_READY` | `LOAD STATUS` перед пакетом (бит caps 4) | `LD_READY` | ядро с медленной памятью ведёт его |
| Монтировщик: монтирование | `IMG_SLOT`, `IMG_SIZE` × 8 дважды, `IMG_FLAGS`, `IMG_PHYS` | `IMG MOUNT` (слот, размер, флаги: защита от записи, физический дисковод) одним пакетом | сигналы монтирования `img_sdc` | нет для дисководов (`sdc_*` остаётся) |
| Монтировщик: запросы | `IMG_LBA` × 4 + `IMG_SEC` в очереди ответов, вытягивание NOP-ами, потерянный кадр = неполный запрос | `IMG EVENT` (вид, слот, LBA) по биту IRQ 3 | секторный интерфейс `img_sdc` | нет |
| Монтировщик: чтение | 512 × `BUF_DATA` + банки или burst, затем сумма в `IMG_LBA` 0/1, затем `IMG_SEC` | `IMG RDATA` (слот, 512 байт, сумма) одним пакетом, ядро отвечает «принято / плохая сумма» в том же пакете; `IMG DONE` | как сейчас | нет |
| Монтировщик: запись | запрос, затем 512 кадров данных + сумма в очереди за ним (очередь должна была их вмещать), вытягивание до 4000 NOP-ами | `IMG WDATA` (слот) одним пакетом читает 512 байт и сумму из секторного буфера ядра | как сейчас | нет |
| Backup RAM (`.sav`) | кадры `CMD_BK_MOUNT`, `CMD_IMG_FLUSH` в обе стороны | `IMG EVENT` вид 4 (размер, вид), `IMG FLUSH`, его ответ `IMG EVENT` вид 3 | `kg_bk_ram` на новой стороне img | нет |
| DSKCHG (дисковод Go) | `CMD_FDD_CHNG` 49 d 00 / 49 d v | `IMG EVENT` вид 5, `IMG FDD_CHNG` | как сейчас | нет |
| RTC | `CMD_RTC` по кадру на регистр: все на старте, время каждые 500 мс; запись CPU по кадру на регистр | `RTC SET` (первый регистр, N значений): весь набор на старте, регистры времени (один пакет около 10 байт) каждые 500 мс; `RTC GET` (число, (регистр, значение) × n) по биту IRQ 6 | RAM регистров `kg_mcu_rtc` (`RTC_A`, `RTC_DI`, `RTC_DO`, `RTC_CS`, `RTC_WR_N`) в `kg_l2_rtc` | нет |
| USB-последовательный порт (ZiFi, RS232) | `CMD_UART` по кадру на байт в обе стороны, счётчик `idx`, кадры DLL / DLM | `PORT 0`: `PUT` / `GET` много байт за пакет, `STATUS` (свободно, доступно, делитель) | FIFO rx / tx с valid / ready, `UART_DLL` / `UART_DLM` | байт + счётчик -> рукопожатие FIFO |
| ESP8266 | `CMD_ESP_UART` по байту, байт держится до подтверждения | `PORT 1`, как порт 0 | FIFO | как выше |
| MIDI IN | `CMD_MIDI` по байту со счётчиком, `MIDI_LOST` | `PORT 2 PUT` много байт | `MIDI_DATA`, `MIDI_WR` | `MIDI_LOST` уходит |
| Принтер | `PRINTER_DATA` на байт + запрос статуса, `PRINTER_STATUS` | `PORT 3 GET` много байт, `PSTAT` статус | FIFO tx, `PRN_BUSY` | нет |
| LED-матрица, индикаторы, отладка | кадры `CMD_MATRIX_CTL` / `PIXEL` / `BITPLAN`, `AUDIO_PEAKS_L/R`, `DEBUG_*` в очереди | `AUX MATRIX` (управление + 32 байта), `AUX PEAKS`, `AUX DEBUG`, бит IRQ 7 | буфер плоскостей, в который ядро рисует (точками или строками), пики, отладочные слова | `MATRIX_CMD` -> буфер |
| OSD | 32 × 26 клеток с 16 цветами, шрифт в FPGA, режим popup, номера popup для своего оверлея ядра | `OSD WRITE` тайлы растра 256 × 128, окна `POPUP` с zoom, `COLORS` | `kg_l2_osd` поверх видео (вместо `kg_osd_overlay`) | видеотракт берёт новый оверлей |
| Bursts | второй chip select, заголовок, `BURST_READY`, биты caps 0..2 | нет: каждый пакет — burst | — | пины burst уходят |
| Целостность | фильтр chip select, суммы секторов, ядро спрашивает снова | фильтр chip select, суммы секторов (чтение и запись), запрос повторяется через 200 мс | — | — |
