# Burst-передачи MCU → FPGA

[English version](burst_protocol.md)

Статус: черновик v1. Сторона прошивки реализована. Ядра, которые её не поддерживают, продолжают работать без изменений.

## Зачем

Обычный линк передаёт один 3-байтовый кадр (`cmd, addr, data`) на каждый байт данных, и MCU_SS переключается вокруг каждого кадра. Для ROM, данных файлового загрузчика и ioctl-данных каждые 256 байт нужны ещё кадры банка (`CMD_ROMBANK`, `CMD_FILEBANK`, `CMD_IOCTL_BANK`). Около 2/3 времени шины уходит на накладные расходы.

Burst передаёт один короткий заголовок, а затем до 512 байт данных подряд, под **второй линией выбора (chip select)**. Обычный протокол и MCU_SS остаются как есть, поэтому старые ядра, которые второй chip select не видят, не затрагиваются.

## Сигналы

| Сигнал | Направление | Назначение |
|---|---|---|
| `BURST_CS_N` | MCU → FPGA | Chip select burst, активный ноль. SCK / MOSI / MISO общие с обычным линком. |
| `BURST_READY` | FPGA → MCU | 1 = FPGA может сейчас принять полный burst (512 байт). Необязателен, см. capabilities. У входа MCU есть подтяжка к земле, поэтому неуправляемая линия читается как 0. |

Назначение выводов. Со стороны RP2040 используются имена из прошивки `PIN_MCU_SPI_IO0/1` из `src/config.h`. **На Go индексы портов FPGA переставлены.**

| Плата | Сигнал | GPIO RP2040 (прошивка) | Порт FPGA в top ядра | Вывод FPGA |
|---|---|---|---|---|
| Go | `BURST_CS_N` | GPIO14 (`PIN_MCU_SPI_IO0`) | `MCU_SPI_IO[1]` | M11 |
| Go | `BURST_READY` | GPIO2 (`PIN_MCU_SPI_IO1`) | `MCU_SPI_IO[0]` | N9 |
| Mini | `BURST_CS_N` | GPIO14 (`PIN_MCU_SPI_IO0`) | `MCU_IO[0]` | G6 |
| Mini | `BURST_READY` | GPIO15 (`PIN_MCU_SPI_IO1`) | `MCU_IO[1]` | F6 |
| Mini G | `BURST_CS_N` | GPIO14 (`PIN_MCU_SPI_IO0`) | `MCU_IO[0]` | G6 |
| Mini G | `BURST_READY` | GPIO15 (`PIN_MCU_SPI_IO1`) | `MCU_IO[1]` | F6 |

**MCU_IO4 недоступен.** На платах Mini до Rev.G с [доработкой тактирования FT812](https://github.com/andykarpov/karabas-mini/blob/master/revF_mod.md) по нему идёт тактовый сигнал FT812 8 МГц, который формирует FPGA. На Rev.G он больше не подключён к RP2040. Прошивка держит GPIO18 входом.

MCU управляет `BURST_CS_N` только после того, как загруженное ядро объявило поддержку burst (см. ниже). До этого вывод остаётся входом, как раньше. При каждой загрузке ядра он возвращается во вход.

## Запрос возможностей (`CMD_CAPS = 0xF7`)

При каждой загрузке ядра MCU спрашивает у него, что оно поддерживает, по обычному линку. Запрос — первый кадр после CONF_DONE, до `CMD_INIT_START`, `CMD_HW_SETUP` и ROM: ответ ещё и сообщает MCU, что ядро работает (сразу после CONF_DONE его линк может быть ещё в сбросе, например пока захватывается PLL).

1. MCU отправляет обычный кадр `{0xF7, 0x00, 0x01}`. `addr = 0x00` означает «запрос», `data = 0x01` — версия протокола.
2. Затем MCU отправляет до 16 кадров `CMD_NOP`. Ядро с поддержкой burst отвечает в **ответных байтах** любой из этих передач (байты, которые FPGA выдвигает на MISO) кадром `{0xF7, caps, max_mhz}`. Ядра, которые отправляют данные в MCU через очередь, могут ответить через неё: кадры, уже стоящие в очереди перед ответом (например, NOP, которые некоторые ядра держат в очереди), только задерживают его и должны оставаться намного ниже 16.
   - `caps`, бит 0: burst-запись поддерживается.
   - `caps`, бит 1: `BURST_READY` управляется ядром. Если 0, MCU его не проверяет.
   - `caps`, бит 2: burst-чтение поддерживается (см. «Burst-чтение» ниже; нужен бит 1).
   - `caps`, бит 3: backup RAM, бит 4: MIDI IN ([protocol.ru.md](protocol.ru.md), раздел 7); биты 7..5: зарезервированы, 0.
   - `max_mhz`: наибольшая частота SCK во время burst, в МГц. 0 означает обычную частоту линка (16 МГц или `spi_freq` ядра). На платах до Mini Rev.G MCU_SCK не заведён на вывод глобального тактирования, поэтому ядро, которое семплирует SCK своей системной частотой, должно указать частоту, которую оно может безопасно передискретизировать.
3. Без ответа MCU отправляет запрос и опрашивает снова, пока ядро не ответит или не пройдёт 100 мс. Ответы на повторные запросы, пришедшие позже, игнорируются.
4. Нет ответа — только обычные передачи. Старые ядра игнорируют неизвестную команду 0xF7.

## Транзакция burst-записи

```
BURST_READY must be 1 (only if caps bit 1)
BURST_CS_N  ‾‾\_________________________________________________/‾‾
MOSI           TYPE  A31..24  A23..16  A15..8  A7..0  D0  D1 ... Dn-1
```

- SPI mode 0, старшим битом вперёд, байты по 8 бит, до `max_mhz`.
- Заголовок: 5 байт, `TYPE`, затем 32-битный стартовый адрес `ADDR` в big-endian.
- Данные: от 1 до 512 байт. Байт `k` записывается по адресу `ADDR + k`. Burst заканчивается, когда `BURST_CS_N` поднимается в 1.
- MCU_SS (обычный) и `BURST_CS_N` никогда не бывают в нуле одновременно.
- Во время burst-записи FPGA не должна управлять MISO (сохраняется обычное поведение: управлять им только пока MCU_SS в нуле). MCU игнорирует MISO во время burst.
- MCU проверяет `BURST_READY` только между burst-ами, но не внутри. Ядро должно держать его в 1 только пока может принять целый burst в 512 байт на частоте `max_mhz`.
- Если `BURST_READY` остаётся 0 в течение 100 мс, MCU до конца этой передачи переходит на обычные кадры.

`TYPE` выбирает цель. Он использует код обычной команды данных, которую заменяет, чтобы ядро могло подать тот же внутренний строб записи:

| TYPE | Заменяет (обычные) | Цель в ядре |
|---|---|---|
| `0x07` (`CMD_ROMDATA`) | `CMD_ROMBANK` + `CMD_ROMDATA` | Загрузчик ROM: `ROMLOAD_ADDR` / `ROMLOAD_DATA` / `ROMLOAD_WR` |
| `0x0D` (`CMD_FILEDATA`) | `CMD_FILEBANK` + `CMD_FILEDATA` | Данные файлового загрузчика |
| `0x53` (`CMD_IOCTL_DATA`) | `CMD_IOCTL_BANK` + `CMD_IOCTL_DATA` | Данные ioctl (файловый загрузчик OSD) |

Бит 7 в `TYPE` = 1 обозначает запрос чтения (см. «Burst-чтение» ниже). Ядро должно игнорировать burst с неизвестным `TYPE`, отбрасывая байты, пока `BURST_CS_N` не поднимется в 1.

Всё вокруг данных остаётся обычным и неизменным: старт/стоп `CMD_ROMLOADER`, сброс/активность `CMD_FILELOADER` и `CMD_IOCTL_STATE` / `SLOT` / `SIZE` / `EXT`. Burst заменяет только кадры банка и данных между ними.

## Burst-чтение (FPGA → MCU), планируется

Статус: описано, но пока не реализовано ни с одной стороны. Предназначено для данных, которые производит FPGA, например секторов диска, записанных ядром для файлового монтировщика. Нужны биты 1 и 2 в caps.

FPGA обычно нужно время, чтобы получить данные (из SDRAM, буфера сектора, ...), поэтому чтение проходит в две фазы chip select, а `BURST_READY` служит квитированием:

```
1. request:  BURST_CS_N low:  TYPE|0x80, A31..24, A23..16, A15..8, A7..0, LEN15..8, LEN7..0   BURST_CS_N high
             FPGA: BURST_READY -> 0, starts fetching LEN bytes from ADDR into its output buffer
2. wait:     MCU waits for BURST_READY = 1 (data is ready), with the same 100 ms timeout
3. data:     BURST_CS_N low:  MCU clocks out 1 + LEN bytes (MOSI = 0x00)
             MISO: 1 turnaround byte (ignored by the MCU), then D0 .. DLEN-1
             BURST_CS_N high
```

- `LEN` равно 1..512, big-endian.
- Байт разворота даёт FPGA время одного байта после падения `BURST_CS_N`, чтобы положить D0 в свой сдвиговый регистр MISO, и ей не нужен первый бит D0 до первого фронта SCK.
- Во время фазы данных, и только тогда, FPGA управляет MISO из burst-логики: `MCU_MISO <= spi_miso when MCU_SS = '0' else burst_miso when BURST_CS_N = '0' and read pending else ...`. Во время фазы запроса и во время burst-записи она MISO не использует.
- После фазы данных чтение закончено. Любой другой burst или новый запрос начинается с заголовка заново. Если MCU не дождался `BURST_READY` по таймауту, он поднимает `BURST_CS_N` без фазы данных; ядро сбрасывает ожидающее чтение при следующем заголовке запроса.
- Сторона MCU (планируется): `link_burst_read(type, addr, buf, len)`, используется только при установленном бите 2 в caps.

## Сторона прошивки

- `link_caps_query()` выполняется в `do_configure()`. `link_burst_available()` / `link_burst_write()` находятся в `src/fpga/link.cpp`.
- Пользователи: `rom_send()` (ROM), файловый загрузчик и загрузчик ioctl. Они переходят на обычные кадры с первого байта, который burst отправить не смог.
- Лог при `debug=1` печатает ответ: `FPGA caps: ...` или `FPGA caps: none (classic link)`.
