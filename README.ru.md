# Прошивка Karabas Go

[![Build](https://github.com/andykarpov/karabas-go-firmware/actions/workflows/build.yml/badge.svg?branch=master)](https://github.com/andykarpov/karabas-go-firmware/actions/workflows/build.yml)

[English](README.md) | Русский

Прошивка микроконтроллера RP2040 (Raspberry Pi Pico) для ретрокомпьютеров на ПЛИС семейства
Karabas Go. Микроконтроллер работает в паре с ПЛИС: загружает ядра (битстримы) с SD-карты,
рисует экранные меню, обслуживает клавиатуры, мыши, джойстики и часы реального времени и
обменивается данными с запущенным ядром по SPI.

**[Маппер USB-геймпадов](https://andykarpov.github.io/karabas-go-firmware/hidmapper/)**: настройка
USB HID геймпада в браузере и загрузка его ini-драйвера для папки `/drivers/` на SD-карте.
Сейчас он нужен редко: большинство геймпадов работает и без драйвера, а плата сама настраивает
геймпад (Setup > Map USB gamepad в OSD ядра, Setup > Gamepad в загрузочном меню), см.
[USB HID геймпады](docs/usb_gamepads.ru.md).

## Платы

| Плата | Прошивка в [karabas-go](https://github.com/andykarpov/karabas-go) | В релизе этого репозитория |
| --- | --- | --- |
| Karabas Go | `firmware/karabas_go.uf2` | `karabas-go-firmware.uf2` |
| Karabas Mini (rev.C .. F3) | `firmware/karabas_mini.uf2` | `karabas-mini-firmware.uf2` |
| Karabas Mini G (rev.G / G2) | `firmware/karabas_minig.uf2` | `karabas-minig-firmware.uf2` |

Ядра — файлы `.kg`, один на ядро для всех плат (`cores/` в karabas-go); прошивка читает и
старые файлы под одну плату `.kg1` / `.kg2` / `.kg3`.

## Возможности

- **Загрузка ядер.** Битстрим уходит в ПЛИС через PIO и DMA, за ним загружаются ПЗУ ядра.
- **Загрузочное меню.** Загрузочное ядро (`boot.kg`, [karabas-go-core-menu](https://github.com/andykarpov/karabas-go-core-menu))
  само рисует меню ядер и свой Setup, на своём процессоре. У прошивки оно запрашивает по линку
  ([docs/link_v2.ru.md](docs/link_v2.ru.md), раздел 5.9, RPC) список ядер, `karabas.ini`, часы и
  USB-геймпады и просит её запустить ядро. Выбранное ядро может запускаться автоматически по
  таймауту, один раз после включения. Для `boot.kg`, слишком старого для этой прошивки (без RPC),
  прошивка показывает сообщение: запишите на карту новый `boot.kg` (BTN2 делает карту
  USB-накопителем).
- **OSD.** Ядра с экранным меню берут из файла ядра свои пункты, переключатели и горячие клавиши.
  Длинное меню прокручивается; ядро может разбить его на подменю (страницы, в том числе
  вложенные), разделители и пункты, которые видны или доступны только при определённом значении
  другого пункта (ключи `core.json` описаны в
  [make_core](https://github.com/andykarpov/karabas-go-tools/blob/master/make_core/README.ru.md#подменю-страницы-и-условные-пункты)).
  Образы дисков монтируются с SD-карты и остаются открытыми, пока работает ядро, с чтением и
  записью. Поддерживаются и загрузчики файлов: их список файлов начинается в каталоге ядра,
  заходит в подкаталоги и куда угодно на карте и открывается в каталоге последнего загруженного
  файла (он хранится в `karabas.ini`); у ядра-загрузчика с пунктами меню они открываются
  из списка файлов по Tab или O (Options), Esc возвращает к файлам. Списки файлов скрывают
  скрытые и системные записи и имена, начинающиеся с `.`, и показывают каталоги первыми. На Karabas Go вместо образа можно выбрать
  физический дисковод.
- **Растровый OSD.** Ядра на линке v2 ([docs/link_v2.ru.md](docs/link_v2.ru.md), все текущие
  ядра) получают монохромный OSD 256x128, который рисует MCU (u8g2), с именами в UTF-8
  (кириллица): переключатели Off / On — это флажки (Space или Enter переключает), Enter на
  переключателе с несколькими вариантами открывает их список, а Setup (часы, маппер
  USB-геймпадов) и About — последние пункты главного меню. Старые ядра остаются на текстовом OSD
  линка v1.
- **Ввод.**
  - USB-клавиатуры (в том числе NKRO) и мыши.
  - USB HID геймпады: раскладка строится по их HID-дескриптору, либо задаётся ini-драйвером из
    [маппера](https://andykarpov.github.io/karabas-go-firmware/hidmapper/) или из OSD.
  - XInput-геймпады (проводной протокол Xbox 360, например 8BitDo M30 2.4G).
  - PS/2-клавиатуры.
  - USB MIDI-клавиатуры, для ядер, которые принимают MIDI.
  - Сега-джойстики в разъёмах платы (Karabas Go).
  - Любой джойстик приходит в ядро как 6-кнопочный геймпад Sega Mega Drive.
- **USB host.** Работает на втором ядре RP2040 через PIO-USB, хабы поддерживаются. Драйвер
  USB-принтера (Epson LX-300+II) в работе.
- **Часы реального времени.** Настраиваются в Setup RTC в OSD или на странице Clock
  загрузочного меню (с часовым поясом и синхронизацией NTP) и передаются в ядро.
- **Wi-Fi** модуля ESP8266: загрузочное ядро само настраивает его в своём Setup (поиск сетей,
  подключение, Forget, Upgrade / Reset module) и синхронизирует часы по NTP; пока работает его
  Setup, uart модуля у ядра. Прошивка соединяет uart модуля с USB-serial портом
  (`AT+KARABAS=esp`).
- **SD-карта как USB-накопитель.** Компьютер видит SD-карту как USB-флешку, вынимать её из платы
  не нужно.
- **USB-serial мост.** Два USB-serial порта: управляющий (лог и команды `AT+KARABAS=`,
  управляющие прошивкой) и порт ядра, UART ядра байт в байт.
  USB-UART переходник, вставленный в USB host, занимает место порта ядра.
- **Дополнительная периферия**, определяется при старте: OLED-дисплей, LED-матрица,
  I2C-расширитель (Go), ESP8266, MIDI (Mini G). FT812 сбрасывается перед каждым ядром, кроме
  загрузочного; ядра, которые им пользуются, управляют им сами.
- **Быстрая передача.** Ядра линка v2 получают каждое сообщение одним пакетом (сектор, блок ПЗУ
  до 512 байт) и поднимают линию прерывания, когда им есть что передать MCU; старые ядра линка v1,
  которые это поддерживают, получают ПЗУ и файлы пакетами до 512 байт по второму chip select.

## Где взять прошивку

Каждая сборка `master`, которая меняет прошивку, становится
[релизом](https://github.com/andykarpov/karabas-go-firmware/releases) с тремя `.uf2` файлами.
Эти же файлы попадают в `firmware/` репозитория [karabas-go](https://github.com/andykarpov/karabas-go),
релизного репозитория всех плат (вместе с ядрами): `karabas_go.uf2`, `karabas_mini.uf2`,
`karabas_minig.uf2`.

### Тестовая прошивка из pull request

CI собирает прошивку для каждого PR. Скачать её может любой, кто вошёл в GitHub, права на
репозиторий не нужны.

1. Откройте страницу PR и перейдите на вкладку **Checks**.
2. Выберите слева **Build**, затем **Summary** в самом верху левой колонки.
3. Внизу страницы, в блоке **Artifacts**, скачайте `firmware`.
4. Распакуйте zip и прошейте файл своей платы (`karabas_go.uf2`, `karabas_mini.uf2` или
   `karabas_minig.uf2`), как описано в разделе
   [Обновление прошивки](#обновление-прошивки).

На **Checks** показан прогон последнего коммита PR, это самая свежая сборка. Это тестовая
прошивка, не релиз: чтобы вернуться на стабильную, прошейте `.uf2` из
[Releases](https://github.com/andykarpov/karabas-go-firmware/releases). GitHub хранит
артефакты 90 дней.

## Обновление прошивки

1. Переведите RP2040 в режим BOOTSEL: зажмите кнопку **Boot**, нажмите и отпустите **Reset**,
   затем отпустите **Boot**. Другой способ: отправьте `AT+KARABAS=boot` в USB-serial порт платы.
2. Появится USB-накопитель `RPI-RP2`. Скопируйте на него `.uf2` файл для своей платы.
3. Плата перезапустится с новой прошивкой.

## SD-карта

| Путь | Что это |
| --- | --- |
| `/boot.kg` | ядро загрузочного меню ([karabas-go-core-menu](https://github.com/andykarpov/karabas-go-core-menu)), загружается при включении: меню ядер и его Setup |
| `/*.kg` | ядра: один файл для всех плат (формат kgo2, [docs/kgo2.md](https://github.com/andykarpov/karabas-go-tools/blob/master/docs/kgo2.md)), показываются, если в файле есть эта плата. Файл ядра только читается: изменённое в меню хранится в `/config` |
| `/*.kg1` (`.kg2`, `.kg3`), `/boot.kg1` (...) | ядра в старом формате kgo1 под одну плату, по-прежнему читаются (`boot.kg` важнее, если есть оба); настройки их меню пишутся в сам файл ядра |
| `/config/<id ядра>.ini`, `.eep` | настройки ядра `.kg`: опции, отличные от значений по умолчанию, образы, последний файл загрузчика; его EEPROM. Создаёт прошивка; About (`A` в меню ядра) > `R` удаляет их |
| `/karabas.ini` | настройки, необязательно, см. ниже |
| `/drivers/*.ini` | драйверы USB-геймпадов, необязательно ([формат](docs/usb_gamepads.ru.md#ini-драйвер)) |
| `<save_dir>/` или `<каталог игры>/saves/<игра>.sav` | backup RAM ядер, у которых он есть (NES...), создаёт прошивка; игра — файл загрузчика или пункта `FL` (Doom: WAD); у ядра с `loader` `save_name` в `core.json` одно имя на всё (`<save_name>.sav`) |

Файловая система: FAT16, FAT32 или exFAT. Ядра собираются утилитой
[make_core](https://github.com/andykarpov/karabas-go-tools/tree/master/make_core) из
[karabas-go-tools](https://github.com/andykarpov/karabas-go-tools).

### karabas.ini

Файл необязателен: без него прошивка берёт значения по умолчанию из таблицы ниже. Все ключи,
кроме `[fileloader]` и `[setup] watchdog`, меняются в Setup загрузочного меню (разделы System,
Autoload, Display, Sound, Theme, Clock), которое читает и пишет файл через прошивку. Сохранение
создаёт файл или записывает только изменённые ключи, остальной файл остаётся как был. Строки не
длиннее 78 символов (без конца строки), иначе файл целиком игнорируется.

| Секция | Ключ | По умолчанию | Значение |
| --- | --- | --- | --- |
| `[setup]` | `debug` | `0` | `1`: отладочный лог в USB-serial порт |
| | `watchdog` | `1` | при `debug=1`: `0` выключает сторож зависаний (сброс через 8 с без продвижения главной задачи, причина — в логе следующей загрузки) |
| | `dvi_only` | `0` | `1`: ядра отключают HDMI-фреймы (звук, инфокадры) и выдают чистый DVI |
| | `core_sort` | `name` | порядок списка ядер: `name` (имя ядра), `file` (имя файла), `order` (поле `order` ядра, затем имя); загрузочное ядро всегда первое |
| | `tz` | `+00:00` | смещение от UTC для NTP sync, задаётся на странице Clock загрузочного меню, например `+03:00`, `-04:30`; без летнего времени |
| `[ft812]` | | | вид загрузочного меню (секция сохранила имя меню FT812, которым была) |
| | `sound` | `1` | звук запуска меню: `0` нет, `1` Klyuchik, `2` Ta-dan, `3` Run, `4` Sound 4 |
| | `click` | `1` | `1`: щелчок при нажатии клавиши |
| | `time`, `date`, `char` | `1`, `1`, `1` | показывать в меню часы, дату и картинку «Карабаса» |
| | `color_bg`, `color_gradient`, `color_button`, `color_active`, `color_text`, `color_text_active`, `color_copyright` | `010101`, `0000c8`, `202026`, `0000c8`, `ffffff`, `ffffff`, `787878` | цвета (hex RGB) |
| | `mouse_speed` | `3` | скорость указателя мыши в меню, 1..5 |
| | `video_mode` | `0` | видеорежим меню: `0` 640x480, `1` 800x600 (60 Гц VESA; другое число — 640x480); Setup > Display > Video mode включает режим на пробу и через 15 с возвращает прежний, если его не оставить (Keep) |
| `[matrix]` | `enabled`, `brightness`, `clock_*`, `meter_*` | `1`, `0`, ... | LED-матрица, см. [docs/matrix.ru.md](docs/matrix.ru.md) |
| `[autoload]` | `enabled`, `timeout`, `core` | `0`, `15`, нет | запуск ядра с этим id (`id` в `core.json`, например `tsconf`) через `timeout` секунд; один раз после включения, не после возврата в меню |
| `[fileloader]` | `<id ядра>` | нет | каталог последнего файла, загруженного ядром-загрузчиком в старом формате `.kgN` (пишет прошивка; пусто или нет ключа — каталог ядра); ядро `.kg` хранит его в `/config/<id ядра>.ini` |

Пример:

```ini
[setup]
debug=0
tz=+03:00

[ft812]
sound=2

[autoload]
enabled=1
timeout=5
core=tsconf
```

## Управление

| Клавиши | Джойстик | Действие |
| --- | --- | --- |
| Menu (Win) + Esc | Start + C, Start + Select | открыть / закрыть OSD запущенного ядра |
| Ctrl + Alt + Backspace | Start + X | вернуться в загрузочное меню (загружается boot-ядро, микроконтроллер и его USB-устройства продолжают работать, без автозапуска); в загрузочном меню: перезапустить микроконтроллер |
| стрелки, Enter, Esc | крестовина, A / B, C или Select | навигация по меню (удержание направления — автоповтор); кроме самого маппинга геймпада |
| Left | Left | назад, где у Left нет другой роли: меню Setup, About |
| цифры | Up / Down | цифра под курсором в поле даты / времени |
| `S` (загрузочное меню) | Start | Setup загрузочного меню |
| `S`, `A` (OSD ядра) | | Setup (часы, маппер USB-геймпадов), About |
| Space (OSD ядра, растровый OSD) | | переключить флажок (переключатель Off / On) |
| Enter, Right (OSD ядра) | A / B, Right | открыть подменю пункта `►` |
| Esc (OSD ядра) | C или Select | из подменю в меню уровнем выше; в главном меню (или в списке файлов ядра-загрузчика) закрывает OSD |
| Delete / Backspace (OSD ядра) | | извлечь образ диска выбранного привода |
| Backspace (список файлов) | | родительский каталог |
| `H` (список файлов ядра-загрузчика) | | назад в каталог ядра |
| `R` (список файлов ядра-загрузчика) | | перечитать список |

Ядра могут задавать свои горячие клавиши OSD. В загрузочном меню клавиши, геймпады и мышь идут в
меню загрузочного ядра, у которого свои клавиши.

## Кнопки на плате

Что делают кнопки **BTN1** и **BTN2**, задаёт каждое ядро (`buttons` в его `core.json`, см.
`make_core` в karabas-go-tools): передать в ядро (reset, NMI... как решит ядро; по умолчанию),
открыть OSD, вернуться в меню, перезагрузить ядро, перезагрузиться в BOOTSEL или в USB mass
storage — по нажатию или по удержанию. В загрузочном меню BTN1 перезагружает в BOOTSEL, BTN2 — в
USB mass storage (удержание 2 с — со второй SD-картой).

Перезагрузка ядра идёт через загрузочное ядро, которое заполняет SRAM нулями (0.2 с): ядро
стартует с чистой памятью, как из меню.

## SD-карта как USB-накопитель

Нажмите **BTN2** в загрузочном меню или отправьте `AT+KARABAS=msc` в serial порт. Плата покажет
компьютеру свою SD-карту как USB-накопитель, остальное в это время не работает, об этом сообщает
OSD поверх загрузочного меню. Чтобы вернуться в обычный режим, извлеките накопитель на компьютере.

Так же работает и вторая SD-карта (слот FPGA, ей пользуются ядра): удерживайте **BTN2** в
загрузочном меню 2 секунды или отправьте `AT+KARABAS=msc2`. Накопитель называется «SD Card 2» и
работает медленнее (около 300 КБ/с). Если в слоте нет карты, плата вернётся в меню.

## USB-serial мост

### Два serial-порта

Плата показывает два USB-serial порта:

| Порт | Linux (постоянное имя) | Что это |
| --- | --- | --- |
| управляющий (интерфейс 0) | `/dev/serial/by-id/usb-Karabas_Go_<серийник>-if00` | отладочный лог и команды `AT+KARABAS=` ниже; UART ядра здесь нет (с прошивки 2026-11-19: используйте порт ядра) |
| порт ядра (интерфейс 2, «Karabas core serial») | `/dev/serial/by-id/usb-Karabas_Go_<серийник>-if02` | только UART ядра, байт в байт: без команд, без лога, без пауз между байтами (getty, передача файлов, двоичные протоколы) |

Номера `ttyACM` зависят от порядка появления портов (и от других ACM-устройств), поэтому
пользуйтесь именами из `by-id` (или `by-path`, они привязаны к USB-разъёму). Короткие имена даёт
правило udev:

```
# /etc/udev/rules.d/60-karabas.rules
SUBSYSTEM=="tty", ATTRS{idVendor}=="2e8a", ATTRS{idProduct}=="000a", ENV{ID_USB_INTERFACE_NUM}=="00", SYMLINK+="karabas-ctl"
SUBSYSTEM=="tty", ATTRS{idVendor}=="2e8a", ATTRS{idProduct}=="000a", ENV{ID_USB_INTERFACE_NUM}=="02", SYMLINK+="karabas-serial"
```

В macOS порты называются `/dev/cu.usbmodem<серийник>1` и `...3`, в Windows это два COM-порта
(второй в диспетчере устройств называется «Karabas core serial»). Открытие порта на 1200 бод,
перезапускающее плату в BOOTSEL, работает только на управляющем порту.

На управляющем порту на строки, начинающиеся с `AT+KARABAS=`, отвечает сама прошивка; остальные
байты отбрасываются (в UART ядра они больше не идут):

| Команда | Действие |
| --- | --- |
| `AT+KARABAS=list` | список ядер на SD-карте с их сборками |
| `AT+KARABAS=version` | `+KARABAS:<прошивка>;<плата>;<id ядра>;<сборка ядра>`: сборка прошивки, плата (1 Go, 2 Mini, 3 Mini G) и запущенное ядро |
| `AT+KARABAS=boot` | перезапуск в режим BOOTSEL для обновления прошивки |
| `AT+KARABAS=msc` | перезапуск с SD-картой как USB-накопителем |
| `AT+KARABAS=msc2` | перезапуск со второй SD-картой (слот FPGA) как USB-накопителем |
| `AT+KARABAS=sd2test` | только в загрузочном ядре: чтение второй SD-карты на нескольких частотах SPI (проверка карты и линка) |
| `AT+KARABAS=esp` | только в загрузочном ядре: мост переключается на ESP8266, для его AT-команд (CR, LF или CR LF из терминала уходят как CR LF) |
| `AT+KARABAS=uart` | обратно на UART ядра |
| `AT+KARABAS=key:<клавиши>` | нажать и отпустить клавиши, как USB-клавиатура (ядро, OSD, горячие клавиши): клавиши через пробел, каждая из модификаторов и одной клавиши через `+` (`ctrl+alt+del`, `menu+esc`, `menu+f3`, `enter`, `f12`, `0x29` код HID), 100 мс нажата, 40 мс отпущена |
| `AT+KARABAS=type:<текст>` | набрать текст (печатный ASCII, раскладка US) |
| `AT+KARABAS=hold:<клавиша>` / `release` | держать клавишу (до `release` или следующей клавиши) / отпустить все клавиши, кнопки мыши и геймпада |
| `AT+KARABAS=sync` | `OK`, когда всё, что поставили в очередь `key`, `type`, `mouse`, `click` и `pad`, доставлено |
| `AT+KARABAS=mouse:<dx>,<dy>[,<кнопки>[,<колесо>]]` | движение, как от USB-мыши (каждая ось до 4000); кнопки: бит 0 левая, 1 правая, 2 средняя, не указаны или пусто: нажатые остаются |
| `AT+KARABAS=click[:left\|right\|middle]` | щелчок мыши (по умолчанию левой) |
| `AT+KARABAS=pad:<порт>:<кнопки> ...` / `padhold:<порт>:<кнопки>` | нажать и отпустить кнопки геймпада на USB-порту джойстика 0 или 1, например `pad:0:up up+a` / держать их до `release` или следующего `pad`. Кнопки: up down left right start a b c x y z mode |
| `AT+KARABAS=state` | `+KARABAS:core;<файл>;<id>;<имя>;<сборка>;<boot, osd, fileloader или hidden>`, `+KARABAS:osd;<открыт>;<экран>;<браузер файлов открыт>` (экран `core_browser`: загрузочное ядро), затем строка `item` на каждый файловый пункт |
| `AT+KARABAS=load:<файл или id>` | запустить ядро из любого ядра, `OK`, когда оно запустилось; загрузочное ядро — загружается заново, без перезагрузки MCU |
| `AT+KARABAS=reset` | запустить текущее ядро заново с чистой памятью; в загрузочном ядре — загрузочное ядро заново, без перезагрузки MCU |
| `AT+KARABAS=osd` / `osd:<пункт>` / `osd:<пункт>=<значение>` | пункты меню ядра: `+KARABAS:item;<поз>;<ключ>;<имя>;<вид>;<доступен>;<номер значения>;<значение>;<варианты или расширения>`; задаётся номером или именем варианта, триггер — `=1` |
| `AT+KARABAS=mount:<пункт>:<путь>` / `eject:<пункт>` | образ файлового пункта, сохраняется как выбранный в OSD. Пункт — его ключ или имя (регистр любой) или `#<поз>`; аргумент строки не длиннее 80 символов |
| `AT+KARABAS=debug:0` / `debug:1` | отладочный лог выкл. / вкл. до следующей перезагрузки; `karabas.ini` не меняется |
| `AT+KARABAS=usbhub` / `usbhub:<порт>` / `usbhub:<хаб>.<порт>` / `usbhub:scan` / `usbhub:stall` | USB-хабы: `+KARABAS:usbhub;<адрес>;<mounted или enumerating>;pipe <armed или not armed>` и `+KARABAS:usbport;<хаб>;<порт>;<empty, enumerating, mounted или failed>;<устройство>;<перезапуски>`; порт первого хаба (или хаба по адресу) перечисляется заново, его устройство сначала удаляется / следующее перечисление порта хаба встаёт в самом начале (как при сработавшей проверке внутри TinyUSB). Проверка восстановления: устройство за хабом, чьё перечисление не удалось или встало, перечисляется заново само, до 3 раз (в логе при `debug=1`) |

### USB-UART переходник

USB-UART переходник (CDC ACM, FTDI, CP210x или CH34x), вставленный в USB host платы, пока он
вставлен, занимает место порта ядра: байты ядра уходят в переходник, а байты из него в ядро, байт в
байт. Переходник работает в 8N1 на скорости ядра: 115200 или скорость, которую задаёт ядро
(делитель DLL / DLM в ZX Evo RS232). Используется только первый переходник. Порт ядра в это время
ничего не получает; управляющий порт остаётся для отладочного лога и команд `AT+KARABAS=`.

## Сборка из исходников

Прошивка написана на C11 на pico-sdk с FreeRTOS SMP и TinyUSB, собирается CMake и тулчейном
arm-none-eabi от earlephilhower ([pico-quick-toolchain](https://github.com/earlephilhower/pico-quick-toolchain)
4.1.0: нужен его newlib). Версии pico-sdk и FreeRTOS зафиксированы в `CMakeLists.txt` и
скачиваются сами, если `PICO_SDK_PATH` / `FREERTOS_KERNEL_PATH` не заданы.

```sh
cmake -S . -B build -G Ninja                  # -DPICO_TOOLCHAIN_PATH=..., если тулчейна нет в PATH
ninja -C build                                # все платы
ninja -C build karabas_minig                  # одна плата: karabas_go, karabas_mini, karabas_minig
cmake -S test -B build-test -G Ninja && ninja -C build-test && ctest --test-dir build-test   # юнит-тесты
```

Результат: `build/karabas_<плата>.uf2`, его копируют на диск `RPI-RP2` платы в режиме BOOTSEL
(туда переводит `AT+KARABAS=boot` по USB). CI ([build.yml](.github/workflows/build.yml))
собирает все платы, запускает тесты и выпускает релизы. Маппер геймпадов лежит в
[`tools/hidmapper`](tools/hidmapper) и публикуется в GitHub Pages через
[hidmapper.yml](.github/workflows/hidmapper.yml).

Архитектура описана в [CLAUDE.md](CLAUDE.md) (на английском): задачи и блокировки, модули,
формат файла ядра и соглашения по коду.
